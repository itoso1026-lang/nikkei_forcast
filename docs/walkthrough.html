日経平均終値予測の作り方

毎朝8時の時点でわかっている情報だけを使って、その日の日経平均の終値を当てるモデルを作りました。この資料では、データ集めから評価、毎朝の予測と API までの手順を、図と表で順番に説明します。

課題（学習・検証）として作ったもので、実際の売買には使いません。コードは GitHub のリポジトリにあります。

問題を決める

最初に「いつの時点で、何を、何と比べて当てるのか」を決めました。ここがあいまいだと、評価の数字が何を意味するのかわからなくなります。

項目決めたこと
予測する時点毎営業日の朝 8:00（日本時間）
当てるものその日の日経平均（^N225）の終値
使ってよい情報8:00 より前に確定したデータだけ
モデルLightGBM（決定木の勾配ブースティング）をメインに、XGBoost・CatBoost と比べる
合格の考え方簡単な予測（ベースライン）との差を、期間ごとに正直に報告する。勝てなくても結論として成立する
主な評価指標bp-MAE（予測と実績の差の平均。1bp = 0.01%）

なぜ「8時」と「確定」にこだわるのか。あとから見れば、過去のデータは全部そろっています。気をつけないと、本当はまだ知らないはずの値（未来の情報）をモデルに渡してしまい、成績が実力以上に良く見えます。これをリークと呼びます。

全体の流れ

作業は大きく2つに分かれます。過去のデータでモデルを作って確かめる「バックテスト」と、できたモデルで毎朝予測する「運用」です。

順コマンドやること
1check_bar_boundariesデータの「1日の区切り」の時刻を確かめる
2fetch_data2010年からのデータを取得して保存する
3data_quality欠損・異常値・おかしな値を調べる
4features時刻を合わせて特徴量の表を作る
5tuneLightGBM の設定を自動で探す（Optuna、50回）
6train全パターンを walk-forward で学習・予測する
7evaluateベースラインと比べ、表と図を作る
8train --final本番用のモデルを全データで学習する
9predict_todayその日の予測を出してログに残す
10evaluate_live毎朝の予測と、あとで出た実績を照合する

コマンドはどれも .venv\Scripts\python -m src.<名前> で実行します。

Step 1

データを集める

無料で使える yfinance というライブラリで、2010年1月から現在までの日足（1日1本の値動き）を集めました。日経平均は朝の時点で動いていないので、夜のあいだに動く海外の市場と先物が主な材料になります。

グループティッカー使い道
当てるもの^N225日経平均。終値が正解データ
日経先物（CME）NIY=F, NKD=F夜のあいだの日経平均の動き。いちばん大事
米国株^GSPC, ^IXIC, ^DJI, ^SOX前夜の米国市場
為替6J=F, JPY=Xドル円。6J=F は CME の円先物
金利・恐怖指数^TNX, ^VIXリスクの強さ
欧州・商品^GDAXI, ^STOXX50E, CL=F, GC=F欧州株・原油・金
日本株の ADRTM, SONY, MUFG と東京の 7203.T など米国で取引された日本株と、東京の終値の差

工夫した点。取得したデータは parquet 形式で保存し、2回目からは新しい分だけを取ります。データの取り方は DataSource というクラスにまとめたので、将来、大阪取引所の夜間先物の CSV に差し替えることもできます。

Step 2

データの時刻を確かめる

日足には「2026年10月8日」のような日付しか付いていません。でも、その日のデータが何時に確定したのかがわからないと、朝8時に使えたかどうか判断できません。そこで、1時間ごとのデータ（1時間足）と日足を突き合わせて、1日の区切りの時刻を調べました。

データ日足に入る最後の時刻確定時刻として設定した値朝8時に使える日
日経平均・東京の株16:00 JST16:00 JST前日（t−1）まで
米国株16:30 NY時間17:15 NY時間（＝ 6:15〜7:15 JST）前日の夜（米国の t−1）まで
CME 先物15:00 シカゴ時間16:00 シカゴ時間（＝ 6:00〜7:00 JST）前日の夜まで
欧州株18:00 ドイツ時間22:30 ドイツ時間前日の夜まで
ドル円 JPY=X01:00 ロンドン時間翌日 0:00 ロンドン時間（＝ 8:00〜9:00 JST）2日前 まで

設定した時刻には、さらに30分の余裕を足しています。実際より少し遅めにしておけば、まだ確定していない値を使ってしまう心配が減るからです。

ここでわかったこと。CME 先物の「10月8日」の日足は、日本時間の10月8日の朝から10月9日の朝までの取引です。つまり東証の10月8日の取引時間を丸ごと含んでいます。10月8日の予測にこの足を使うと、その日の答えを先に見ることになります。

Step 3

データの品質を調べる

モデルを作る前に、データそのものがおかしくないかを調べました。無料のデータには、欠けている日や、明らかに変な値が混ざっていることがあるからです。

日経平均（^N225）

欠けている日はなし。東京の個別株には、祝日なのに値がある行が21日分あったので、日経平均の取引日をカレンダーの正解にしました。

急な値動き

平均から大きく外れた日を調べると、どれも東日本大震災、コロナ、2024年8月の急落など、本当に起きた動きでした。値は直さず、印だけ付けています。

NIY=F（円建て先物）

約6割の日で、始値・高値・安値・終値が全部同じ値でした。中には、終値が「前日の東証の終値」とほぼ同じになっている日がありました。

どう扱ったか。仕様どおり、比べる相手（B1）は NIY=F のままにしました。そのかわり「NIY の値が平らな日か」と「NIY と NKD の差」を特徴量に入れ、モデルが自分で補正できるようにしました。この判断が、あとで結果の読み方に大きく関わります。

Step 4

未来の情報を混ぜない（リーク防止）

Step 2 で調べた確定時刻を、すべてのデータの行に「確定時刻」の列として付けました。予測する日ごとに「確定時刻が朝8時より前の行のうち、いちばん新しいもの」を選びます。下の表は、10月8日（木）の予測で、CME 先物とドル円のどの行が選ばれるかの例です。

データ日足の日付終値確定時刻（JST）10/8 の予測に使う？
CME 先物 NIY=F10/670,58510/7 6:30使える（古い）
CME 先物 NIY=F10/769,56010/8 6:30これを使う
CME 先物 NIY=F10/868,42010/9 6:30使えない 8時より後
ドル円 JPY=X10/6―10/7 8:30これを使う
ドル円 JPY=X10/7―10/8 8:30使えない 8時より後

この仕組みにすると、「日本の祝日明けには、東証の前営業日より新しい米国のデータを使う」「ドル円は2日前の値を使う」といったルールが、個別に書かなくても自然に守られます。

チェック 1：確定時刻の検査

特徴量の表を作るたびに、使った全データの確定時刻が朝8時より前かをプログラムで検査します。1行でも違反があればエラーで止まります。

チェック 2：未来を消すテスト

ある日の朝8時より後に確定したデータを全部消してから、特徴量を作り直します。値が1つでも変われば、未来の情報を使っていた証拠です。実データの3日分で、変わらないことを確かめました。

チェック 3：成績が良すぎたら疑う

先物の値（B1）より15%以上良い結果が出たら、リークを疑うメッセージを出します。今回は約3%で、その心配はありませんでした。

Step 5

特徴量を作る

特徴量は、モデルに渡す「ヒント」の列です。全部で73個作りました。価格そのもの（例：50,000円）は時代によって水準が変わってしまうので使わず、すべて変化率や比率にしています。

種類例考え方
先物先物と前日の東証終値の差、NIY と NKD の差夜のあいだにどれだけ動いたか
海外市場米国株・欧州株の1日・5日・20日の変化率、半導体と NASDAQ の差前夜の世界の流れ
リスクVIX の水準と変化、米国金利の変化市場がどれだけ不安か

Step 6

何を当てるかを決める（目的変数）

終値そのものを当てるのではなく、ある基準の値から「何%動くか」を当てて、あとで価格に戻します。基準の取り方を2通り試しました。

Step 7

比べる相手を決める（ベースライン）

モデルの成績は、それだけ見ても良いのか悪いのかわかりません。誰でも思いつく簡単な予測（ベースライン）と比べて、初めて意味が出ます。

Step 8

時系列のまま検証する（walk-forward）

普通の機械学習のようにデータをランダムに分けると、未来のデータで学習して過去を当てることになってしまいます。そこで、時間の順番を守って「過去で学習 → 次の1か月を予測」を、1か月ずつずらしながらくり返しました。これを walk-forward 検証と呼びます。

early stopping 方式A

学習期間の最後の6か月で成績を見ながら、良くならなくなったところで学習を止めます。止めた回数（ラウンド数）を記録します。

early stopping 方式B

それまでの方式Aのラウンド数の中央値を使い、6か月も含めた全期間で学習し直します。結果は方式Bのほうが良くなりました。

チューニング

Optuna で LightGBM の設定を50通り試しました。最後の1年は「最終テスト（holdout）」として、チューニングには使っていません。

試した組み合わせは、目的変数2通り × モデル3種類 × 損失関数2通り × 学習期間2通り × 方式A・B の48パターンと Ridge です。さらに、4つのモデルの単純平均と、予測を組み合わせるスタッキングも作りました。16コアのパソコンで約31分かかりました。

Step 10

毎朝の予測と API

本番用のモデルを全データで学習して保存し、毎朝 7:30 にパソコンのタスクスケジューラから予測を実行します。CME のデータがまだ確定していないときは、無理にモデルを使わず、警告を付けて先物の値（B1）をそのまま出します。

保存した結果は、FastAPI で作った API からも取り出せます。自分のパソコンの中だけで動かし、外部には公開しません（データ源の yfinance が非公式のサービスのため）。

メソッドパス返すもの
GET/healthモデルのバージョンと、各データがいつのものか
GET/predict/today今日の予測
GET/predict/{date}指定した日の予測
POST/predict/runデータを取り直して予測を実行
GET/predictions期間内の予測と、実績との差
POST/model/reload新しいモデルを読み込み直す

テストは28個あり、リーク検査、カレンダー、API のエラー処理（休場日・実行中・未来の日付）などを自動で確かめています。

わかったこと

簡単な予測が強い

朝の先物の値（B1）だけで、前日の終値より誤差が約23%小さくなります。夜のあいだの情報は、ほとんど先物に入っているからです。

モデルの上乗せは小さい

機械学習で上乗せできたのは約3%（約7円）でした。リーク検査を通ったうえでの数字なので、この小ささが正直な実力です。

改善の中身を確かめる

改善の多くは、2021年の先物データの不具合を補正した分でした。数字が良くなったときは、どこで良くなったのかを分けて見ることが大切です。

急変には弱い

2024年8月の急落では、どのモデルも B1 より悪い結果でした。過去のパターンから外れた日には、簡単な予測のほうが安全なことがあります。

データは後から変わる

yfinance は昨日の先物の値を朝のうちに書き換えていました（68,495円 → 68,420円）。朝に取った値と、あとで検証に使う値は同じとは限りません。

時刻は自分で確かめる

日付だけでは「いつ使えたか」はわかりません。1時間足と突き合わせて区切りの時刻を調べたことで、ドル円の落とし穴に気づけました。
